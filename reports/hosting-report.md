# Публикация сайта и сравнение бесплатных хостингов

Проверено 11 ноября 2026 года. Объект работы — учебный сайт «Лапа рядом». В исходной папке был статический лендинг на Tailwind CSS без Vue, Vite и удалённого Git-репозитория. Для задания добавлен монтируемый Vue-компонент рекламного места; основной сайт остаётся статическим. Сайт опубликован на альтернативной платформе GitHub Pages: **https://mugwaw.github.io/lapa-ryadom-ads/**. Исходники: **https://github.com/Mugwaw/lapa-ryadom-ads**. Cloudflare Pages остаётся предпочтительным вариантом для будущего подключения реальной рекламы, однако авторизация Cloudflare в этой среде недоступна.

## Риски политики

У Cloudflare Pages отсутствие найденного запрета на рекламу следует формулировать осторожно. Это вывод из опубликованных правил и тарифных документов, а не обещание, что любой рекламный формат будет принят. Если подключать внешнюю рекламную сеть, дополнительно придётся соблюдать её собственные правила, требования к содержимому и обработке данных. Для учебного плейсхолдера такой сети пока нет: он не показывает объявления, не загружает сторонние скрипты и не собирает статистику. Поэтому на данном этапе вопрос фактической монетизации ещё не возникает.

GitHub Pages в официальных дополнительных условиях описан как площадка прежде всего для показа личных и организационных проектов. Документ прямо допускает отдельные способы монетизации, включая кнопки пожертвований, однако запрещает превращать Pages в бесплатный хостинг онлайн-бизнеса или сервиса, ориентированного прежде всего на коммерческие транзакции [6]. Поэтому один умеренный рекламный блок у содержательного проекта выглядит менее рискованным, чем сайт, построенный в основном ради рекламы, но отдельного общего разрешения именно для AdSense в приведённом положении нет. При существенном росте коммерческой доли контента выбор GitHub Pages надо пересмотреть.

В случае Netlify форум поддержки несколько раз подтверждал, что бесплатный план можно использовать для коммерческих проектов [10]. Это полезное разъяснение, но ответ сотрудника на форуме не равен условию договора и не описывает все варианты сторонней рекламы. Кроме того, 300 кредитов расходуются совместно на production deploy, трафик и запросы: нельзя переводить их в один постоянный месячный лимит ГБ. Например, после одного production deploy остаётся 285 кредитов, и только теоретически это 14,25 ГБ трафика без учёта запросов и других операций [9]. Для рекламного сайта с непредсказуемыми пиками это заметный эксплуатационный риск.

Vercel прямо ограничивает Hobby личным некоммерческим применением в условиях обслуживания [13]. У рекламного проекта появляется намерение получать доход, поэтому рассчитывать на Hobby для такого сценария нельзя без отдельного подтверждения платформы. Его технические лимиты сами по себе достаточны для небольшого Vue-сайта, но договорное ограничение важнее удобства сборки. Использовать Vercel здесь разумно лишь для учебной версии без реальной монетизации.

## Рекомендация и основания

Предпочтительный вариант — Cloudflare Pages: опубликованные документы для бесплатных статических ресурсов не устанавливают лимит на количество запросов, а Pages даёт 500 сборок в месяц и прямую интеграцию с Git [1, 2, 4]. Для данного проекта команда `npm run build` создаёт содержимое `dist`, поэтому стандартная настройка Pages подходит без изменения путей публикации; `base: '/'` соответствует домену `*.pages.dev` [4]. В качестве альтернативы беру GitHub Pages, если сайт остаётся учебным или проектным, а реклама играет второстепенную роль [6]. Netlify возможен при контроле расхода кредитов, а Vercel Hobby для оплачиваемой рекламы не рекомендую [9, 13].

При выборе важнее всего три фактора. Первый — предсказуемость правил монетизации: блокировка аккаунта после набора аудитории нанесёт больший ущерб, чем разница в удобстве панели управления. Второй — запас по отдаче статических файлов, потому что вместе с рекламным блоком растут показы страниц, изображений и скриптов; у Cloudflare статические запросы не лимитированы отдельно по ГБ [1]. Третий — автоматическая сборка из GitHub: она позволяет воспроизводимо собирать Vue-компонент и Tailwind при каждом обновлении, а не загружать вручную папку, состояние которой трудно сверить с исходниками [4]. Для небольшого учебного сайта предел в 500 сборок в месяц заведомо не узкое место; больший практический риск сейчас — отсутствие удалённого репозитория.

## Состояние публикации и артефакты

Компонент `src/AdSlot.vue` поддерживает размеры `banner` и `sidebar`, а также произвольные `width` и `height`. Он монтируется после секции услуг на главной странице. Сборка `pnpm build` прошла, браузерный тест обнаружил надпись «Рекламное место» и не зафиксировал ошибок JavaScript. Скриншот: `reports/ad-slot-desktop.png`. GitHub Actions успешно выполнил сборку и публикацию; главная страница, `styles.css` и `ad-slot.js` отвечают HTTP 200. При последующем переходе на Cloudflare Pages настройка будет такой: Build command — `npm run build`, Output directory — `dist` [4]. Пока действуют ограничения GitHub Pages на назначение сайта и трафик [5, 6], реальную рекламу следует размещать умеренно и только как дополнение к содержимому проекта.
